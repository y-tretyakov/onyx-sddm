# Stage 0.3 — CI skeleton + metadata.desktop + theme.conf Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use subagent-driven-development to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Stage 0.3 Phase 0 — сделать тему installable для SDDM (`metadata.desktop` + `theme.conf`), починить root/scale скелет (follow-up F1/F2/F3/F6 из code review 0.1+0.2), добавить CI skeleton, поднять версию до `0.0.3`.

**Architecture:** `theme/onyx/` становится installable SDDM-темой: `metadata.desktop` (Desktop Entry, `QtVersion=6`) + `theme.conf` (skeleton, exposed как `config`). `Main.qml` — корневой full-screen `Rectangle` с `import QtQuick` (Qt6, без версии), который инстанцирует `ThemeState` и красит фон из color API (F1+F6). `ThemeState.qml` — надёжный паттерн scale (F2): `s` вычисляется в визуальном root `Main.qml` (где `Screen` гарантирован) и передаётся в `ThemeState`, оставаясь единым источником scale. `validate.sh` расширяется required-набором `metadata.desktop` + `theme.conf` (F3). CI skeleton — GitHub Actions workflow `validate.yml` (validate.sh + qmllint), проходит даже при пустом вызове.

**Tech Stack:** Qt6 / QML, bash, GitHub Actions (`ubuntu-latest`).

**Spec:** `docs/ROADMAP.md` §3 Phase 0 stage 0.3 («CI skeleton + metadata.desktop + theme.conf | CI проходит (даже пустой)») + follow-up F1/F2/F3/F6 из `docs/code-reviews/2026-09-08-stage-0.1-0.2.md` + `docs/ARCHITECTURE.md` §3, §4, §9 + рекомендации `sddm-theme` skill (metadata.desktop / theme.conf / scale).

### Task 2: Main.qml — Qt6 full-screen root + wire ThemeState (F1 + F6)

**Files:**
- Modify: `theme/onyx/Main.qml` (полная замена)

**Interfaces:**
- Consumes: `ThemeState.qml` (Task 3, но независимо создаётся id `state`); `config` object (из theme.conf через SDDM, в preview может отсутствовать → безопасный fallback)
- Produces: корневой `Rectangle`, `width: Screen.width`, `height: Screen.height`, `color` из бэкграунда; инстанцирует `ThemeState { id: state }`; вычисляет `readonly property real s: Screen.height / 768` и передаёт в `state.s` (данный потомок полагается на Task 3)

- [ ] **Step 1: Rewrite Main.qml**

Rewrite `theme/onyx/Main.qml`:

```qml
import QtQuick

Rectangle {
    id: root
    width: Screen.width
    height: Screen.height
    color: state.bgColor

    readonly property real s: Screen.height / 768

    ThemeState {
        id: state
        s: root.s
    }
}
```

Note: `state` создаётся как child root; `root.s` вычисляется в визуальном контексте, где `Screen` гарантирован. `bgColor` — из ThemeState (Task 3). Значение `state.bgColor` по умолчанию `"#000000"` (совпадает с theme.conf), при отсутствии `sddm`/`config` не падает.

### Task 3: ThemeState.qml — reliable scale pattern (F2)

**Files:**
- Modify: `theme/onyx/ThemeState.qml` (полная замена)

**Interfaces:**
- Consumes: `s` (real) устанавливается из `Main.qml` (Task 2); `config` (theme.conf `bgColor`) — опционально, защищённо
- Produces: `ThemeState { property real s; readonly property color bgColor; readonly property bool isPreview }` — единый источник scale и фонового цвета

- [ ] **Step 1: Rewrite ThemeState.qml**

Rewrite `theme/onyx/ThemeState.qml`:

```qml
import QtQuick

QtObject {
    id: themeState

    property real s: 1

    readonly property bool isPreview: typeof sddm === "undefined" || sddm.hostName === undefined

    readonly property color bgColor: {
        if (!isPreview && typeof config !== "undefined" && config.bgColor)
            return config.bgColor
        return "#000000"
    }
}
```

Note (decision ADR): `s` больше НЕ вычисляется внутри через `Screen` (чтобы не зависеть от резолва `Screen` в bare-`QtObject` — F2). Значение приходит из визуального root `Main.qml` (Task 2), где `Screen` гарантирован. ThemeState остаётся единым владельцем scale для всех компонентов (ARCHITECTURE §4.3) и добавляет `bgColor` (ARCHITECTURE colour API, §4.3) с безопасным fallback для превью (graceful degradation §1.6).

- [ ] **Step 2: qmllint syntax check**

Run:
```bash
qmllint theme/onyx/ThemeState.qml
```
Expected: exit code 0, нет output.

- [ ] **Step 3: Commit**

```bash
git add theme/onyx/ThemeState.qml
git commit -m "stage(0.3): reliable scale via visual root (F2)

- s passed from Main.qml, not computed in QtObject
- add bgColor with preview-safe config fallback"
```

### Task 5: CI skeleton — GitHub Actions workflow

**Files:**
- Create: `.github/workflows/ci.yml`

**Interfaces:**
- Consumes: `validate.sh` (Task 4), `theme/onyx/` QML-файлы (Tasks 1–3)
- Produces: GitHub Actions workflow `ci` с job `validate`, который прогоняет `validate.sh` и `qmllint` на QML-файлах темы; проходит (ROADMAP «CI проходит (даже пустой)»)

- [ ] **Step 1: Write .github/workflows/ci.yml**

Write `.github/workflows/ci.yml`:

```yaml
name: ci

on:
  push:
    branches: [main, dev]
  pull_request:

jobs:
  validate:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4

      - name: Install qmlint
        run: |
          sudo apt-get update
          sudo apt-get install -y qml6-module-qtquick qmllint6

      - name: Validate theme file set
        run: ./validate.sh

      - name: QML syntax check
        run: |
          set -euo pipefail
          while IFS= read -r f; do
            qmllint6 "$f"
          done < <(find theme/onyx -name '*.qml' -type f)
```

Note: `find` здесь — runtime-команда CI-шага (не операция рабочего каталога), допустима в контексте workflow. `qmllint6` (Ubuntu 24.04) — пакет с qmllint для Qt6; на момент написания имя пакета/бинаря может отличаться — субагент проверяет и при необходимости корректирует имя бинаря (fallback `qmllint`), сохраняя суть: прогон по всем `*.qml` темы.
