# Stage 1.1 Hotfix — preview.sh Window import + honest -W/-H + ARCHITECTURE sync

> **For agentic workers:** REQUIRED SUB-SKILL: subagent-driven-development. Steps use checkbox (`- [ ]`) syntax.

**Goal:** Исправить три реальных замечания после PR #8: (1) неявный импорт `Window` в генерируемом wrapper'е preview.sh; (2) честная семантика `-W/-H`/`-o` (тема рендерится по `Screen`, а не по размеру окна); (3) синхронизация ARCHITECTURE.md (замена устаревших `qmlscene`/`QuickShell`).

**Architecture:** preview.sh генерирует временный wrapper `.qml` в `/tmp`. Theme root (`Main.qml`) жёстко привязан к `Screen.width/height` — значит размер окна wrapper не равен разрешению рендера темы. Правки: явный `import QtQuick.Window`, честная документация в `--help` (какие размеры реально контролируются, какие нет), архитектурные упоминания `qmlscene`/`QuickShell` → `qml6`/`qml`.

**Tech Stack:** bash, Qt6/QML preview (qml6), Markdown.

**Spec:** замечания пользователя 2026-09-08 (три пункта) + `docs/ARCHITECTURE.md` §1, §8, §9 + `docs/superpowers/plans/2026-09-08-stage-1.1-review-followups.md` (CR-4/R4).

- [ ] **Step 2: Обновить usage/Notes честной семантикой**

Обновить текст `usage()`/Notes так, чтобы явно и коротко указывалось:

- `-W/-H` задают размер **окна** wrapper'а (viewing window), НЕ разрешение рендера темы. Theme root привязан к `Screen.width/height` (Main.qml), поэтому при `-W/-H`, отличных от разрешения экрана, тема рендерится по `Screen`, а окно показывает лишь часть/пустоту вокруг — правки Main.qml не будет.
- Без `-W/-H` тема рендерится на полный экран текущего дисплея.
- `-o FILE.png` сохраняет скриншот в натуральном размере theme root = текущее `Screen.width` × `Screen.height` (не размер окна).
- Для честного Visual QA в конкретном разрешении (1920×1080 / 2560×1440) нужен дисплей этого разрешения или Xvfb — задокументировать, что это вне текущего скрипта (tech debt → stage 3.8).

Формулировки — краткие, английские, без воды.
